What the three ways cost

The three exhibit pages look the same. They do not load the same. This page opens each of them in a frame and reads the browser's own measurements with the Performance API.

What to expect

  • External CSS is render-blocking. By default the browser does not paint a page until the stylesheets in its head have arrived and been parsed (web.dev: Render blocking CSS, MDN: Critical rendering path). style.css is a second request before first paint.
  • But it is cached on its own. The file is a separate resource, so every page that links it can reuse the stored copy (MDN: HTTP caching). How long the copy is used without asking the server depends on the server's cache headers.
  • Internal and inline CSS travel inside the HTML. No extra request, but no separate cache entry either: the rules are downloaded again with every page that repeats them (unless the HTML itself is cached), and inline styles repeat on every element.

Measure it here

Each press loads external.html, internal.html and inline.html once more. The first run is usually the cold one; on the second, style.css may come from the cache or be revalidated (a small transfer with no body). Numbers vary with network, device, server and what is already cached: compare the pages within one run, not with someone else's numbers.

What each line means: HTML bytes and CSS bytes are the encoded body sizes of the page and of style.css; transferred is what crossed the network, 0 when the copy came straight from the cache. Render-blocking is the resource's renderBlockingStatus (MDN), reported by Chromium-based browsers only. First paint and first contentful paint come from Paint Timing (MDN), in milliseconds from the start of that frame's navigation; a browser may not report them for every frame.

So which one?

The advice on the front page holds, now with reasons: shared look in an external file, because the cache pays for the extra request after the first page; page-specific tweaks in a <style> block; inline only when there is no other way, because it repeats with every element and beats every normal author rule; only !important rules and animations beat it (see the cascade).

Sources: web.dev, MDN: PerformanceResourceTiming, MDN: PerformancePaintTiming.

Which rule wins, and why

The three exhibit pages give the same rules from a file, a <style> block and a style attribute. That is one corner of a bigger machine. When several declarations set the same property on the same element, the browser sorts them through a fixed list of steps, the cascade, and the first one in that order wins. Specificity is only step five.

The six steps

The order below is the cascade sorting order in CSS Cascading and Inheritance Level 5, section 6.1. A later step only matters when every earlier step ties.

  1. Origin and importance. Where the declaration comes from: the browser (user agent), the user, or the page author. Normal author beats normal user beats normal user agent. !important turns the list upside down: important user agent beats important user beats important author. (CSS transitions sit above all of them and animations between important author and normal author.)
  2. Context. Declarations from different encapsulation contexts, such as a shadow tree and the page around it. For normal rules the outer context wins, for important rules the inner one.
  3. Element-attached styles. A style attribute beats any selector with the same origin and importance. This is why inline CSS wins on the exhibit pages, and it is decided before layers and specificity.
  4. Layers. @layer blocks are ordered by first appearance, and styles outside any layer count as one final, implicit layer. For normal declarations the later layer wins; for important ones the earlier layer wins.
  5. Specificity. Ids, then classes, attributes and pseudo-classes, then type selectors: (1,0,0) beats (0,9,9).
  6. Order of appearance. If everything else ties, the declaration that comes last in the document wins. That is the rule the exhibit pages show between a <link> and a later <style>.

Cascade explainer

A small demo page. Pick an element and a property: the table lists every declaration that applies to it, sorted by the six steps, with the step where each loser dropped out. Switch declarations on and off or make them !important. The author styles are applied for real in the frame, and the browser's computed value is checked against the sort.

The page's author CSS starts with @layer reset, base, theme; so reset is the first layer and unlayered styles come after theme. Try making both layered rules important on the first element: the early reset layer now wins, the reverse of the normal order. Then make the style attribute important as well.
